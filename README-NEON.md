# AutoPrime v9 — Neon вместо Supabase

Товары, цены, заказы и клиенты хранятся в PostgreSQL Neon, а фото/видео,
загруженные через мини-приложение, — в Neon Object Storage. Render хранит
лишь временный кеш: после перезапуска файлы восстанавливаются из облака.
Медиа, добавленные через чат бота, по-прежнему используют Telegram file_id.

BYN, категории «Обвесы»/«Диски», статус «Предзаказ» и интерфейс сохранены.
Supabase для этой версии НЕ нужен.

Архив содержит код, но не создаёт проект и не подключает ваш Render автоматически.

## 1. Создайте проект Neon

Откройте https://console.neon.tech и создайте проект, например `autoprime`.

**Выберите AWS Europe (Frankfurt), регион `aws-eu-central-1`.**
Согласно документации Neon, Object Storage сейчас доступен также в AWS Ohio,
N. Virginia и Singapore. Не выбирайте произвольный регион или Azure:
PostgreSQL может быть доступен там, где Object Storage ещё недоступен.

Для приложения используйте одну постоянную ветку проекта, например `main`
или `production`. И база, и хранилище должны относиться к этой же ветке.

## 2. Создайте хранилище фотографий

В проекте выберите нужную ветку и откройте **Object storage → New bucket**:

- имя: `autoprime`;
- доступ: **private**.

Публичный доступ и настройки CORS для приложения не нужны: с Storage
работает только сервер. В bucket храните фото/видео каталога, не личные документы.

Если вкладки Object storage нет, проверьте регион проекта. Открывающийся
сайт Neon ещё не означает, что Storage доступен в каждом регионе.

## 3. Возьмите настройки подключения

### База PostgreSQL

В Neon нажмите **Connect**, выберите нужную ветку, базу и роль владельца
(обычно `neondb_owner`). Скопируйте **connection string** PostgreSQL.
Пул соединений (pooled connection) поддерживается.

Используйте полную строку с паролем и SSL-параметрами, без команды `psql`,
внешних кавычек и незаменённых `[YOUR-PASSWORD]`.
Если пароль вставляете вручную, специальные символы должны быть URL-кодированы.

Приложение само создаст таблицы. Роль подключения должна иметь право
создавать и изменять свои таблицы. Row Level Security включается автоматически;
доступ осуществляется сервером как владельцем таблиц, не из браузера покупателя.

### Фотографии

Откройте **Connect → Storage → Parameters only** (или клиент Python).
Скопируйте в настройки Render:

- `AWS_ENDPOINT_URL_S3` — точный HTTPS endpoint выбранной ветки;
- `AWS_ACCESS_KEY_ID` — S3 Access Key ID;
- `AWS_SECRET_ACCESS_KEY` — S3 Secret Access Key;
- `AWS_REGION` — регион, который показывает диалог подключения.

Используйте значения из Neon, не собирайте endpoint вручную.
Права credentials должны включать `storage:write` (оно включает чтение);
можно выбрать оба `storage:read` и `storage:write`.
При необходимости создайте отдельный credential в **Settings → Credentials**.

**Не путайте S3 Secret Access Key с Neon API key, api_token или паролем БД.**
Для приложения не нужен управляющий ключ NEON_API_KEY.

Пароль, ключи и строку подключения не отправляйте в чат, не добавляйте
в GitHub и не вставляйте в index.html. Храните их в Environment Render.

## 4. Добавьте переменные Render

Откройте ваш существующий сервис Render → **Environment**:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string из Neon Connect |
| `AWS_ENDPOINT_URL_S3` | Из Neon Connect → Storage |
| `AWS_ACCESS_KEY_ID` | Из Neon Connect → Storage |
| `AWS_SECRET_ACCESS_KEY` | Из Neon Connect → Storage |
| `AWS_REGION` | Из Neon Connect → Storage |
| `STORAGE_BUCKET` | `autoprime` |
| `CURRENCY_SIGN` | `BYN` |

Сохраните прежние BOT_TOKEN, ADMIN_IDS, WEBAPP_URL и остальные настройки бота.
Переменные SUPABASE_* больше не используются, их можно удалить из этого сервиса.

## 5. Обновите приложение и разверните

Замените файлы в корне подключённого репозитория содержимым этого архива.
Обязательно обновите **cloud_storage.py, database.py, main.py, Dockerfile
и requirements.txt**, а не только index.html.

Сохраните изменения в GitHub и дождитесь деплоя Render либо выберите
**Manual Deploy → Deploy latest commit**.

Без Docker: установка — `pip install -r requirements.txt`, запуск —
`python main.py`. Для Docker используется Dockerfile из архива.

Эта версия не запустится на Render без полного набора настроек внешней БД
и файлов. При недоступности Neon она не переключается на временную SQLite:
лучше явная ошибка, чем незаметная повторная потеря товаров.
При запуске проверяется доступ к bucket; проверить права на запись позволяет
загрузка тестового товара.

## 6. Обязательно проверьте перезапуск

1. Добавьте тестовый товар с фотографией.
2. Проверьте наличие записи в базе и файла в Object storage → autoprime.
3. Перезапустите Render.
4. Заново откройте мини-приложение: товар, цена и фото должны остаться.
5. Проверьте редактирование и добавление ещё одной фотографии.

Не удаляйте проект, ветку или bucket: данные приложения зависят от них.
После подключения изменение DATABASE_URL или storage endpoint на новую
пустую ветку также меняет видимый набор данных.

## Старые данные

Новая база Neon изначально пустая. Удалённые при прежнем перезапуске фото
без резервной копии восстановить невозможно. Если копии нет, добавьте
товары и фото заново после настройки.

Если сохранились SQLite orders.db и папка uploads:

1. Сделайте отдельную копию исходных файлов.
2. Остановите бот на время переноса.
3. На компьютере с резервной копией установите requirements.txt и задайте
   те же переменные окружения DATABASE_URL и AWS_*.
4. Выполните:

```
python migrate_to_cloud.py --db /путь/к/копии/orders.db --uploads /путь/к/копии/uploads
```

Скрипт читает исходную SQLite в режиме read-only и переносит только в пустую
внешнюю базу. Сначала проверяет исходные фото и загружает их в Storage,
затем переносит записи одной транзакцией и восстанавливает счётчики ID.
При отсутствии исходных фото останавливается. Для переноса медиа из чата
нужен тот же Telegram-бот (file_id привязан к боту).

Если перенос прервался до записи БД, в Storage могут остаться файлы.
Повторный запуск с той же копией безопасно перезапишет те же имена.
Во время переноса не запускайте приложение. После переноса исходную копию
не удаляйте.

Перенос уже заполненной Supabase/PostgreSQL этим скриптом не реализован:
для него нужен отдельный экспорт базы и файлов. Это не требуется, если
Supabase ранее не был настроен.

## Ограничения

Бесплатные тарифы имеют квоты и могут меняться. Проверяйте текущие условия:
https://neon.com/pricing

В приложении оставлен лимит одного фото/видео **50 МБ**. Постоянное хранилище
защищает от перезапуска Render, но не заменяет независимые резервные копии
базы и файлов и не защищает от удаления проекта или превышения квот.

## Частые ошибки

- **Object storage нет в меню:** проверьте поддерживаемый AWS-регион проекта.
- **БД не подключается:** проверьте полную DATABASE_URL, пароль и SSL.
- **Нет доступа к Storage:** проверьте S3-ключи и права storage:write.
- **Bucket не найден:** имя должно совпадать с STORAGE_BUCKET; проверьте ветку.
- **SignatureDoesNotMatch:** перепроверьте Secret Access Key, endpoint и регион.
- **После обновления нет прежних товаров:** новая база пустая; нужен перенос
  сохранённой копии или повторное добавление.
